## 4. 負の転移（Negative Transfer）の分析

### 4.1 負の転移の証拠

**定義**: 学習によりターゲットドメインでの性能が**低下**する現象

**Phase5_v4での負の転移**:
1. **ドメインミスマッチ**: ACSデータ（急性冠症候群）→ 産婦人科テスト
2. **性能低下**: 90% → 80%（-10ポイント）
3. **推論能力の低下**: ベースモデルの長い思考プロセス → 学習済みモデルの空の思考

### 4.2 負の転移の原因仮説

1. **ドメイン固有知識の上書き**:
   - ACSデータでの学習が、ベースモデルの産婦人科知識を上書き
   - 321ヘッドの学習により、汎用的な医療推論能力が損なわれた

2. **過度な簡略化**:
   - ACSデータの答えが簡潔すぎる可能性
   - 学習済みモデルが思考プロセスをスキップする傾向

3. **PRECISE_LEVEL 3の影響**:
   - qkv_proj + o_projの学習により、出力が過度に簡略化
   - 複雑な推論が必要な問題で性能低下

4. **学習データの偏り**:
   - ACSデータ（9,196サンプル）が特定の推論パターンに偏っている
   - 産婦人科のような異なる推論パターンに適応できない

### 4.3 ベースモデルの優位性

**Qwen3-14Bベースモデルの特徴**:
- **事前学習の質**: 大規模な事前学習により、幅広い医療知識を獲得
- **汎用推論能力**: 32,768トークンの推論空間を活用した詳細な思考
- **ドメイン汎化**: 事前学習により、様々な医療ドメインに対応可能

**学習の悪影響**:
- 321ヘッドのSPT学習が、ベースモデルの汎用性を損なった
- 特定ドメイン（ACS）への過度な適応が、他のドメインに悪影響

## 6. 重要な教訓

### 6.1 モデル評価における教訓

1. **モデルカードは必読**: 推奨設定に従わないと性能を60%過小評価（30% vs 90%）
2. **公平な比較が必須**: ベースモデルと学習済みモデルで同一設定を使用
3. **greedy decodingは禁物**: Qwen3では性能が大幅に低下

### 6.2 SPT学習における教訓

1. **ベースモデル性能の確認**: 学習前にベースモデルの性能を正確に評価
2. **ドメインマッチング**: 学習データとテストデータのドメインを一致させる
3. **負の転移のリスク**: クロスドメイン学習は性能を低下させる可能性
4. **汎用性vs専門性**: ベースモデルの汎用性を犠牲にする価値があるか検討

### 6.3 Qwen3モデルの特性

1. **事前学習の質が高い**: ファインチューニング不要な可能性
2. **推論能力が優秀**: 32,768トークンの思考で複雑な問題を解決
3. **ドメイン汎化性が高い**: 産婦人科のような専門知識でも高精度

## 8. 推奨事項

### 8.1 Phase5_v4の問題点と対策

**問題点**:
1. ベースモデルより性能が低い（90% → 80%）
2. クロスドメイン学習による負の転移
3. 推論プロセスの簡略化

**対策**:
1. **同一ドメインでの学習**:
   - ACSデータではなく、産婦人科データ（somemodels）で学習
   - ドメインマッチングにより負の転移を防ぐ

2. **学習率の調整**:
   - 2e-5 → 5e-6に下げる（よりソフトな更新）
   - ベースモデルの知識を過度に上書きしない

3. **学習データの精査**:
   - ACSデータが簡潔すぎる可能性
   - 推論プロセスを含むデータを使用

4. **選択的学習**:
   - 321ヘッド全体ではなく、144医療ヘッドのみ
   - または、推論ヘッド（36個）を除外

### 8.2 今後の実験計画

**実験1: somemodelsデータでの再学習**
```
- データ: somemodels (1,761サンプル)

- 期待結果: 90%以上（ドメインマッチング）
```

```
- 期待結果: ベースモデルの知識を保持しつつ改善
```

**実験3: 選択的ヘッド学習**
```
- データ: somemodels
- ヘッド: 144（医療ヘッドのみ）
- PRECISE_LEVEL: 3
- 学習率: 2e-5
- 推論設定: 推奨
- 期待結果: Phase5の成功（100%）を再現
```

### 8.3 ベースモデルの活用

**結論**: Qwen3-14Bベースモデルは**そのまま使用**が最善の可能性

**理由**:
1. 90%の高精度（推奨設定）
2. 幅広いドメインに対応
3. ファインチューニングのリスク（負の転移）

**推奨**:
- プロンプトエンジニアリングで精度向上

## 10. 結論

### 10.1 主な発見

1. **ベースモデル（Qwen3-14B）の優秀性**:
   - 推奨設定で**90%**の高精度
   - 幅広い医療ドメインに対応
   - **事前学習の質が非常に高い**

2. **SPT学習の失敗**:
   - ACSデータでの学習により性能が**10%低下**
   - **負の転移（Negative Transfer）**の実例
   - ドメインマッチングの重要性

3. **推奨設定の重要性**:
   - greedy decoding: 30%
   - **推奨設定**: 90%
   - **60ポイントの差**（200%向上）

4. **評価方法の重要性**:
   - ベースモデルと学習済みモデルで**同一条件**が必須
   - モデルカードの推奨設定に従う
   - 公平な比較により真の性能を把握

### 10.2 最終評価

**Phase5_v4の評価**: ❌ **失敗**

**理由**:
- ベースモデル: 90.0%
- 学習済みモデル: 80.0%
- **10ポイントの性能低下**
- 学習コスト（8GPU、11分）に見合わない結果

**ベースモデル（Qwen3-14B）の評価**: ✅ **優秀**

**理由**:
- 推奨設定で90%の高精度
- ファインチューニング不要
- **そのまま使用が最善**

### 10.3 重要な教訓

1. ✅ **モデルカードを必ず読む**
2. ✅ **推奨設定を遵守する**
3. ✅ **ベースモデルの性能を正確に評価する**
4. ✅ **同一条件で比較する**
5. ⚠️ **クロスドメイン学習は慎重に**（負の転移のリスク）
6. ⚠️ **ベースモデルが優秀な場合、ファインチューニングは不要**

### 10.4 今後の方向性

**推奨アプローチ**:
1. **Qwen3-14Bベースモデルをそのまま使用**
2. **プロンプトエンジニアリングで精度向上**
3. **Few-shotプロンプトで95%以上を目指す**

**ファインチューニングを行う場合**:
1. **同一ドメインのデータを使用**（somemodels）
2. **低学習率**（5e-6以下）
3. **選択的ヘッド学習**（144ヘッド以下）
4. **定期的な評価**（性能低下を早期発見）
